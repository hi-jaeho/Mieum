# Mieum Frontend 구조 안내

이 문서는 Mieum 프론트엔드의 폴더와 파일이 각각 어떤 역할을 맡는지 설명합니다.

Mieum은 **Mieum 사원 간의 내부 협업**과 **Mieum 사원·고객 간의 소통**을 위한 업무 메신저입니다. 공개 회원가입은 제공하지 않으며, 관리자만 사원과 고객의 계정을 발급할 수 있습니다.

## 2. 최상위 파일

### `index.html`

React 애플리케이션이 들어갈 HTML 문서입니다.

- `<div id="root">`가 React 화면이 붙는 자리입니다.
- 브라우저 제목, 화면 크기 설정, 페이지 설명을 정의합니다.
- 실제 페이지 UI는 이 파일에 직접 작성하지 않고 React 컴포넌트에서 관리합니다.

비유하면 `index.html`은 건물의 빈 터이고, React가 그 위에 실제 건물을 세웁니다.

### `package.json`

프로젝트 실행 방법과 사용 중인 라이브러리를 기록합니다.

- `npm run dev`: 개발 서버 실행
- `npm run build`: 배포용 파일 생성
- `npm run preview`: 생성된 배포용 파일 미리보기
- `react`, `react-dom`: React 화면 구현
- `react-router-dom`: URL과 페이지 연결
- `vite`: 개발 서버 및 빌드 도구

### `package-lock.json`

설치된 패키지의 정확한 버전을 고정합니다. 다른 컴퓨터에서도 같은 버전의 라이브러리가 설치되도록 도와줍니다.

직접 수정하기보다 `npm install` 명령으로 관리합니다.

### `vite.config.js`

Vite가 React 코드를 이해하고 빌드할 수 있도록 설정합니다.

현재는 필요한 최소 설정인 React 플러그인만 사용합니다.

### `.gitignore`

Git에 포함하지 않을 파일과 폴더를 지정합니다.

- `node_modules`: 다시 설치할 수 있는 라이브러리
- `dist`: 다시 생성할 수 있는 빌드 결과물
- `.DS_Store`: macOS가 자동으로 만드는 파일

### `README.md`

프로젝트 실행 방법, 체험 계정, URL과 전체적인 폴더 구조를 빠르게 확인하는 문서입니다.

### `ARCHITECTURE.md`

현재 읽고 있는 문서입니다. 폴더와 파일의 역할, 데이터 흐름, 백엔드 연결 지점을 자세히 설명합니다.

## 3. `src/` 폴더

실제로 작성한 React 코드가 들어가는 중심 폴더입니다.

페이지, 컴포넌트, 데이터, 서비스와 스타일을 역할별로 나눠 관리합니다. 서랍마다 물건의 종류를 나눠 넣는 것처럼, 코드도 목적에 따라 폴더를 구분했습니다.

### `src/main.jsx`

React 애플리케이션의 시작점입니다.

- `index.html`의 `root`에 React를 연결합니다.
- `BrowserRouter`로 URL 기반 페이지 이동을 활성화합니다.
- `AuthProvider`로 로그인 정보를 전체 앱에 제공합니다.
- `ToastProvider`로 알림 메시지를 전체 앱에 제공합니다.
- 공통 CSS 파일을 불러옵니다.

### `src/App.jsx`

URL과 페이지를 연결하는 라우팅 파일입니다.

| URL | 화면 | 접근 조건 |
|---|---|---|
| `/` | Mieum 소개 | 모두 |
| `/login` | 로그인 | 모두 |
| `/dashboard` | 대화 목록 | 로그인 사용자 |
| `/dashboard/chats/:id` | 선택한 채팅방 | 로그인 사용자 |
| `/profile` | 마이페이지 | 로그인 사용자 |
| `/admin/users` | 사용자 관리 | 관리자 |

`Protected`는 로그인하지 않은 사용자가 업무 화면에 접근하면 로그인 페이지로 보냅니다.

`AdminOnly`는 관리자 이외의 사용자가 사용자 관리 페이지에 접근하면 대시보드로 보냅니다.

공개 회원가입 URL은 존재하지 않습니다.

## 4. `src/components/` 폴더

여러 페이지에서 재사용하거나, 페이지 안에서 분리할 필요가 있는 UI를 보관합니다.

페이지 파일이 너무 많은 역할을 맡지 않도록 돕습니다.

### `src/components/AppLayout.jsx`

로그인 이후 모든 업무 페이지가 공유하는 틀입니다.

- PC 사이드바
- 상단 헤더
- 계정 드롭다운
- 로그아웃
- 모바일 하단 메뉴
- 현재 URL에 따른 페이지 제목
- 관리자 전용 사용자 관리 메뉴

`Outlet` 위치에 대시보드, 마이페이지 또는 관리자 페이지가 들어갑니다.

집의 거실과 복도는 그대로 두고 방의 내용만 교체하는 구조와 비슷합니다.

### `src/components/ChatComponents.jsx`

채팅 기능에서 사용하는 컴포넌트를 모아둔 파일입니다.

#### `ConversationList`

- 사용자가 참여 중인 대화 목록 표시
- 대화 검색
- 사내·고객 대화 필터
- 고객 계정의 진행 중·종료 필터
- 페이지 이동
- 로딩, 빈 목록, 오류 상태 표시

#### `ChatRoom`

- 선택한 대화의 메시지 표시
- 메시지 작성 및 전송
- 날짜와 시간 표시
- 내 메시지와 다른 사용자의 메시지 구분
- 종료된 대화의 입력 제한
- 모바일 대화 목록 복귀

#### `NewChatModal`

- 대화 상대 검색
- 대화 상대 선택
- 대화 제목 입력
- 새 대화 생성
- 관리자 및 사원은 내부 구성원·고객과 대화 가능
- 고객은 Mieum 구성원과 대화 가능

### `src/components/UI.jsx`

작고 재사용 가능한 공통 UI를 모아둔 파일입니다.

#### `Logo`

Mieum 로고와 홈 링크입니다.

#### `Avatar`

사용자의 이름 첫 글자와 역할별 색상을 이용해 프로필 이미지를 대신합니다.

#### `Field`

`label`, `input`, 도움말과 검증 오류를 하나로 묶은 입력 컴포넌트입니다. 접근성을 위해 `label`과 `input`의 ID를 연결합니다.

#### `Loader`

데이터를 불러오는 동안 표시하는 회전 애니메이션입니다.

#### `Empty`

검색 결과 없음, 데이터 없음, 오류 등의 상태를 표시합니다.

#### `Modal`

새 대화와 관리자 계정 생성에 사용하는 공통 모달입니다.

- 배경 클릭으로 닫기
- Escape 키로 닫기
- 모달이 열릴 때 첫 입력 요소로 포커스 이동
- 모달이 닫힐 때 이전 요소로 포커스 복귀

## 5. `src/context/` 폴더

여러 페이지와 컴포넌트가 함께 사용해야 하는 상태를 관리합니다.

상태를 필요한 컴포넌트마다 계속 전달하지 않고, 지정된 Context에서 가져올 수 있습니다.

### `src/context/AuthContext.jsx`

현재 로그인한 사용자를 관리합니다.

- 현재 사용자 불러오기
- 로그인
- 로그아웃
- 마이페이지 정보 수정

로그인 화면, 레이아웃, 대시보드와 관리자 페이지가 같은 사용자 정보를 공유할 수 있게 합니다.

### `src/context/ToastContext.jsx`

화면 오른쪽 아래에 표시되는 짧은 알림을 관리합니다.

예시:

- 사용자 계정 생성 완료
- 프로필 저장 완료
- 처리 중 오류 발생

일정 시간이 지나면 자동으로 사라집니다.

## 6. `src/data/` 폴더

현재 백엔드 대신 사용할 임시 데이터를 보관합니다.

### `src/data/mockData.js`

다음 mock 데이터를 정의합니다.

- 관리자, Mieum 사원과 고객
- 사내 대화와 고객 대화
- 채팅 메시지

사용자 역할은 다음과 같습니다.

| 역할 | 값 | 의미 |
|---|---|---|
| 관리자 | `admin` | 사용자 계정 발급 및 일반 기능 사용 |
| 미음 사원 | `employee` | 내부 구성원 및 고객과 대화 |
| 고객 | `customer` | Mieum 담당자와 대화 |

이 파일의 데이터는 화면에서 직접 가져오지 않습니다. 반드시 `services/mockApi.js`를 통해 사용합니다.

## 7. `src/pages/` 폴더

각 URL에서 보여주는 페이지 단위 컴포넌트를 보관합니다.

페이지는 필요한 컴포넌트를 조립하고 해당 화면의 상태를 관리합니다.

### `src/pages/HomePage.jsx`

Mieum 서비스의 목적을 소개하는 첫 화면입니다.

- Mieum 사내 협업 소개
- Mieum과 고객 간 소통 소개
- 채팅 UI 미리보기
- 로그인 페이지 이동

공개 회원가입 버튼은 제공하지 않습니다.

### `src/pages/AuthPages.jsx`

로그인 화면을 제공합니다.

- 이메일과 비밀번호 입력
- 필수 입력 및 이메일 형식 검증
- 로그인 오류 표시
- 관리자 발급 계정 안내
- 관리자·사원·고객 체험 계정 입력

사용자가 직접 계정을 만드는 기능은 없습니다.

### `src/pages/DashboardPage.jsx`

대화 목록과 선택한 채팅방을 조립하는 업무 메신저의 중심 페이지입니다.

- 대화 검색어, 필터와 현재 페이지 관리
- 대화 목록 불러오기
- 전체 사용자 정보 불러오기
- 새 대화 모달 제어
- 채팅방 URL 연결
- 대화 생성 또는 메시지 전송 후 목록 갱신

선택한 채팅방 ID를 별도 state에 중복 저장하지 않고 URL의 `:id`에서 읽습니다.

### `src/pages/AdminUsersPage.jsx`

관리자 전용 사용자 관리 페이지입니다.

- Mieum 사원과 고객 계정 목록
- 이름, 이메일, 회사와 부서 검색
- 사원·고객 필터
- 페이지 이동
- 사용자 계정 생성 모달
- 계정 생성 입력 검증
- 로딩, 빈 목록, 오류 상태

사원 계정을 만들면 소속 회사는 자동으로 `Mieum`이 됩니다. 고객 계정은 고객사 이름을 입력합니다.

화면의 관리자 메뉴를 숨기는 것에 그치지 않고 `services/mockApi.js`에서도 관리자 역할을 검사합니다.

### `src/pages/ProfilePage.jsx`

로그인한 사용자의 정보를 확인하고 수정하는 화면입니다.

- 이름
- 회사
- 부서
- 직함
- 변경할 수 없는 로그인 이메일 표시
- 필수 항목 검증

관리자, 사원과 고객에 따라 역할명과 소속 정보가 다르게 표시됩니다.

### `src/pages/NotFoundPage.jsx`

정의되지 않은 URL에 접근했을 때 보여주는 404 화면입니다.

사용자가 홈으로 돌아갈 수 있는 버튼을 제공합니다.

## 8. `src/services/` 폴더

데이터를 읽고 변경하는 로직을 보관합니다.

컴포넌트가 mock 데이터나 `localStorage`를 직접 다루지 않도록 중간에서 연결합니다. 식당의 손님이 주방에 직접 들어가지 않고 직원에게 주문하는 것과 같은 구조입니다.

### `src/services/mockApi.js`

현재 실제 서버 대신 사용하는 mock API입니다.

#### `authApi`

- 현재 로그인 사용자 확인
- 이메일과 비밀번호 로그인
- 프로필 정보 수정
- 로그아웃

#### `chatApi`

- 사용자 목록 조회
- 참여 중인 대화 조회
- 채팅방 조회
- 메시지 조회 및 전송
- 새 대화 생성

#### `adminApi`

- 관리자 권한 확인
- 사용자 검색, 필터와 페이지 이동
- 사원 또는 고객 계정 생성
- 중복 이메일 검사

`localStorage`를 사용하기 때문에 브라우저를 새로고침해도 생성한 계정과 메시지가 유지됩니다.

## 9. `src/styles/` 폴더

애플리케이션의 CSS를 보관합니다.

### `src/styles/global.css`

앱 전체에서 공통으로 사용하는 디자인을 정의합니다.

- 블랙·핑크 색상 변수
- 기본 글꼴과 여백 초기화
- 버튼
- 입력 필드
- 로고와 아바타
- 로딩 및 빈 화면
- 토스트
- 모달
- 공통 반응형 규칙

### `src/styles/pages.css`

각 페이지와 큰 컴포넌트의 구체적인 배치를 정의합니다.

- 랜딩 페이지
- 로그인 페이지
- 사이드바와 헤더
- 대화 목록과 채팅방
- 마이페이지
- 관리자 사용자 관리
- PC, 태블릿과 모바일 반응형 레이아웃

CSS 파일을 두 개로 나눈 이유는 공통 부품의 모양과 페이지의 구체적인 배치를 구분하기 위해서입니다.

## 10. `src/utils/` 폴더

특정 화면에 소속되지 않는 작은 도구 함수를 보관합니다.

### `src/utils/helpers.js`

- 이메일 형식 검증 정규식
- 메시지 시간 표시
- 메시지 날짜 표시
- 대화 목록의 날짜와 시간 표시

같은 날짜 형식을 여러 컴포넌트에서 중복 작성하지 않도록 분리했습니다.

## 11. 화면에서 데이터가 이동하는 순서

메시지 목록을 불러오는 과정은 다음과 같습니다.

```text
DashboardPage
    ↓ 요청
chatApi.list()
    ↓ 현재는 localStorage와 mockData 사용
대화 데이터 반환
    ↓
ConversationList 화면 표시
```

관리자가 사용자 계정을 만드는 과정은 다음과 같습니다.

```text
AdminUsersPage
    ↓ 생성 요청
adminApi.createUser()
    ↓ 관리자 역할 검사
    ↓ 입력 데이터 저장
새 사용자 반환
    ↓
목록 갱신 + 완료 토스트
```

## 12. Spring Boot API 연결 시 변경할 부분

주요 교체 대상은 `src/services/mockApi.js`입니다.

예를 들어 현재의 다음 형태를:

```js
const users = getUsers();
return users;
```

나중에는 다음과 같은 실제 요청 형태로 변경할 수 있습니다.

```js
const response = await fetch('/api/users');
return response.json();
```

페이지와 컴포넌트는 같은 서비스 함수를 계속 호출하므로 UI를 크게 고치지 않아도 됩니다.

실제 API 연결 시 서버에서 반드시 확인해야 하는 항목:

1. 로그인과 세션 또는 토큰 검증
2. 관리자 역할 검증
3. 사용자 계정 생성 권한
4. 사용자가 참여한 대화인지 확인
5. 메시지 길이와 입력값 검증
6. 비밀번호 암호화 및 임시 비밀번호 변경 절차

프론트엔드의 권한 검사는 문을 보여주거나 숨기는 안내 역할입니다. 실제 자물쇠 역할의 권한 검사는 Spring Boot 서버에서도 수행해야 합니다.
